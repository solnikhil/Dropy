# PR #31 follow-up review

Reviewed the four local additions at `a1bd42d`: preview event classification,
hidden-source rate monitoring, hand-off decisions, and local build freshness.

Two review fixes:

- Click planning and execution now use the same authorized Accessibility element.
  A replacement element, changed class, or changed pressable ancestor is refused
  before input is sent. Accessibility mutation additionally requires the selected
  window to own the action target.
- Local test builds use a content fingerprint including file paths, resources,
  and the build script. Deletions and edits with old timestamps invalidate it.
  The success marker is removed before a build and published only after the
  whole build succeeds with unchanged inputs.

## Checks

- Native local build and full local suite pass: 100 core XCTest cases plus native
  and shell checks.
- Build-input regressions verify deletion, changed content with old timestamps,
  resource replacement, and timestamp-only changes.
- Device router checks: **30/30 passed**, using only the disposable AppKit input
  fixture. The new regression rebuilds the target field during planning, confirms
  the click is refused, and confirms subsequent typing cannot select that field.
- Resize, stale typing targets, rapid switching, revoked trust, and app-version
  mismatch regressions also pass. Pointer, frontmost app, and desktop did not
  change during router sends. Preferences were restored and the lock released.
- [Raw router log](raw/2026-09-30-pr31-review/router-regressions.log).

The hidden-source monitor and hand-off models are still **not wired into the app**.
Their unit tests verify decisions, not a working UI feature. Real dead-key input
through the updated event handler has not been rerun on the device. Third-party
Electron and media compatibility gates remain unmet, so M3 remains incomplete.
